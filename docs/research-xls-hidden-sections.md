# XLS: empty display sections

## Primary contract

Microsoft's [Format Cells settings](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/format-cells-settings)
describes the positive, negative, zero, and text sections, including leaving a
section blank to hide that class of values. Its [Hide or display cell values](https://support.microsoft.com/en-us/excel/hide-or-display-cell-values)
instructions use `;;;`. Hiding changes the display, not the stored value.
[MS-XLS FORMAT, section 2.4.126](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/300280fd-e4fe-4675-a924-4d383af48d3b)
provides the BIFF record and format-string contract. These sources establish
format semantics; the independent Calc comparison below checks an authored
legacy XLS implementation against them.

## Implemented subset

The existing quote/escape-aware, 64-character grammar now retains empty sections.
Two sections route positive and zero values to the first and negative values to
the second. Three numeric sections route positive, negative, and zero separately.
Selection precedes rounding; both signed zeros take the zero branch. An empty
selected section returns `''`, distinct from the unsupported sentinel `None`.
A wholly empty format string is still unsupported.

Examples: `0;` hides negatives, `;0` hides nonnegative numbers, `0;;0` hides
negatives, `0;0;` hides zero, and `;;;` hides numeric and string displays.
The optional fourth section can be empty or exactly `@`. An absent fourth
section leaves strings unchanged; `;;;@` therefore retains string displays.
All numeric branches must satisfy the existing grammar, including unused ones.
Existing supported fixed, scientific, percent, currency, and literal-affix
sections retain their previous behavior.

Empty numeric sections combined with conditions remain unsupported. The prior
negative-conditional fallback remains unchanged. Color-only sections,
quoted-empty-only sections, date/locale constructs, arbitrary text-section
expressions, malformed quotes/escapes, and more than four sections are not added.
A text display is hidden only when its empty fourth section belongs to a fully
validated unconditional format. Unsupported text formatting retains the existing
raw-string behavior; this change does not add general text-format evaluation.
Boolean and error cells retain their existing displays, even under `;;;`.
Thus this implementation is specifically numeric/string hiding, not a claim to
implement hiding for every BIFF cell type.

## Public data and budgets

`xls.py` already checks numeric results with `is not None`, preserving empty
numeric displays. String hiding is applied only after the existing text charge:
LABEL and cached formula STRING charge on decoding; SST source strings charge
once on decoding and each retained reference is charged again. Hiding does not
let retained strings bypass budgets. Cell and record limits are unchanged.

The public cell retains its typed `value`, `value_type`, and `is_formula`; `text`
is empty. JSON preserves that empty field. `Document.text` excludes empty display
cells. Shared API validation separately budgets retained raw values. No changes
to shared models or API were needed. No formulas, fields, macros, external links,
or commands are evaluated by this feature.

## Original complete XLS and independent oracle

`tests/fixtures/xls_hidden_sections/preserved.xls` is an original authored CFB
workbook, generated by `generate_preserved` in
`tests/test_xls_hidden_sections_ole.py`. It contains 31 cells: 27 numeric cases and
four string cases, with literal independent expected displays. Exact masks are
3–6 characters long; no empty-quote padding changes empty-section semantics.

The generator authors an XLSX using the existing original package skeleton,
exports harmless distinct seed formats with LibreOffice, and patches only
same-size FORMAT character bytes in the resulting XLS. Three-character seeds use
a numeric core and escaped Unicode character; longer seeds use quoted Unicode
literals. LibreOffice shortens a quoted single character to an escape on export,
so such seeds cannot preserve the required three-character size and are not used.
Every patch is length-checked; the complete Workbook stream is read back and
compared to the expected patched bytes.

Verification resolves each cell's XF to its actual FORMAT record, asserts the
exact unpadded mask, and parses that same file through `parse_xls`. A separate
LibreOffice CSV conversion reads the patched XLS, with an assertion that the
input bytes remain unchanged. All 31 displays match. Calc emits an empty CSV
line for one hidden field; the oracle treats that specific representation as one
empty field. It checks row count as well as every display. It does not resave or
normalize the XLS before the comparison.

The persisted XLS has a SHA-256 assertion in the test. The XLSX seed input and
observed CSV are retained beside it. Generation metadata can vary; newly
regenerated files are checked semantically and byte-for-byte against their own
intended patches rather than against the persisted file's checksum.

Reproduce both the persisted and regenerated independent checks:

```sh
OFFICE_CORPUS_LIBREOFFICE=1 .venv/bin/python -m pytest -q tests/test_xls_hidden_sections_ole.py
```

The one- and two-character masks `;`, `;;`, `0;`, and `;0` are covered by synthetic
BIFF tests and the primary section contract, not by this complete-file oracle.
Synthetic tests additionally cover NUMBER, RK, MULRK, numeric and string formula
caches, LABEL and repeated SST references, unsupported grammar, signed zero,
hostile Decimal contexts, exact format-length and text-budget boundaries, and
explicit boolean/error scope controls. No private corpus was used.
