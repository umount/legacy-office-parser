# DOC: строки с разными внешними границами

## Проблема и решение

Отказ от нормализации всей таблицы при разных внешних границах строк терял
также подтверждённые внутренние объединения. Теперь для таблицы с полными,
строго возрастающими границами используется объединение точных координат.
Это выбранная модель извлечения, а не алгоритм визуальной раскладки Word.

Позиции до/после исходной строки представлены `Cell(omitted=True)`.
Они не являются исходными пустыми ячейками или продолжениями объединения.
Для них обязательны пустой текст/блоки, единичные spans, `covered=False`.
Публичная валидация отклоняет нарушенный инвариант; инструмент сравнения
помечает такой результат неполным. Обычный JSON не получает нового false-поля.

Внутренние интервалы одной физической ячейки задаются `col_span` и covered.
Вертикальные объединения сопоставляются по исходным интервалам до добавления
позиций; вложенные таблицы имеют независимые сетки. Даже разница в один twip
не округляется. Полный прирост числа позиций проверяется лимитом до выделения.
Нулевая ширина и неполные границы оставляют исходную структуру с предупреждением.

## Проверка и пределы

Собственный OLE-документ меняет только первую границу одной строки исходного
авторского DOC. Ожидание задано вручную; генератор воспроизводим.
LibreOffice 7.4.7.2 сохраняет его текст и размеры сетки, но представляет
ведущую отсутствующую позицию пустой ячейкой. Сравнение честно сообщает отличие.
Подгонка результата под эту материализацию не выполняется.

В личном корпусе остаются расхождения с геометрией DOCX, полученной через
LibreOffice. Полное совпадение не заявляется. Preferred widths, автоматическая
раскладка и условные стили не вычисляются. Группировка соседних таблиц ещё
не учитывает все свойства позиционирования и идентичности таблиц.

## Основания

- [MS-DOC Tables](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/5b45f0e7-7760-4fdb-af88-0146de2feb4c)
- [TDefTableOperand](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/de06ec41-a0ac-4046-9096-cdfaa0091ad9)
- [OOXML gridBefore](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.gridbefore)

Исходные границы описывают геометрию ячеек; точное объединение координат
является нашим способом сохранить отношения без механизма раскладки.
