# ODF extraction research and implementation decisions

Research performed 2026-10-21 before implementation. The ODF reader is an independent implementation using only `zipfile`, `xml.etree.ElementTree`, and other Python standard-library modules. No odfpy code is copied, combined, adapted, vendored, or imported. No new runtime dependency is needed.

## Sources examined

- [odfpy `teletype.py`, master](https://github.com/eea/odfpy/blob/master/odf/teletype.py), specifically `extractText`: character data alone loses explicit ODF space, tab and line-break elements. The inspected file header declares GPL-2.0-or-later. This mutable revision was consulted for behavior only; no source was adapted.
- [odfpy `opendocument.py`, release-1.4.1](https://github.com/eea/odfpy/blob/release-1.4.1/odf/opendocument.py), especially `__detectmimetype`, `__loadxmlparts`, and `load`. File header: LGPL-2.1-or-later. The loader inspects package MIME and manifest information and loads several XML parts. We do not use its MIME default, XML repair, general object graph, or auxiliary-part loading approach.
- [OASIS ODF 1.2, Part 3: Packages, OASIS Standard, 29 September 2011](https://docs.oasis-open.org/office/v1.2/os/OpenDocument-v1.2-os-part3.html): MIME identification, manifest root media type, ZIP storage, and manifest encryption declarations. Copyright OASIS Open 2002–2011; specification notices apply to the source, which is linked rather than reproduced.
- [OASIS ODF 1.3, Part 3: OpenDocument Schema, OASIS Standard](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part3-schema/OpenDocument-v1.3-os-part3-schema.html): §§5.1.2–5.1.3 headings/paragraphs; §6.1 whitespace and inline text; §9.1 tables, rows, cells and covered cells; §10.2.4 drawing pages; §16.19 notes; repeat, span, value and presentation-class attributes. Copyright OASIS Open 2021. The full HTML exceeded the research browser's response limit; indexed official excerpts and the official PDF were consulted for the relevant sections.
- [OASIS ODF 1.1, OASIS Standard, table-cell and repeat rules](https://docs.oasis-open.org/office/v1.1/OS/OpenDocument-v1.1-html/OpenDocument-v1.1.html): cross-check of repeated rows/cells and explicit covered coordinates. This is a normative reference, not incorporated code.

The selected behavior is small: normalize raw paragraph whitespace while preserving explicit spaces, tabs and breaks; retain row/cell position while interpreting repetitions; emit merge extents; read cached scalar values; keep presentation notes distinct from slide content. General-purpose editing, styling, schema validation and rendering were deliberately excluded.

## Implementation contract

`parse_odf_bytes(data, limits, expected_format=None)` returns the shared `Document`. MIME comes from the `mimetype` member, with manifest root media type as a fallback. An unknown MIME fails rather than defaulting to text. Conflicting MIME declarations, an unexpected format, and mismatched body types fail. A missing manifest is tolerated with an explicit warning. ZIP packaging quirks such as compressed MIME entries are tolerated; this reader is not an ODF conformance validator.

ODT emits paragraphs/headings and tables in body order, including supported list/section wrappers. Headings become `Paragraph` because that model has no heading field. Inline spans are consumed exactly once. Known inline fields (page numbers, dates, times, sequences, references and document fields) retain their stored display text without evaluation or metadata lookup. Explicitly hidden field values are omitted. No warning is emitted merely because a document uses supported text features; master-page omissions warn only when master content is present. Tables preserve repeated cells and rows, span attributes, and empty covered placeholders. Nested tables and inline footnotes/endnotes are currently unsupported and warned about, rather than flattened twice. Repeated objects are independent model instances.

ODS stores only meaningful cells and merge anchors, with one-based coordinates. Empty/covered repeats advance coordinates without allocating cells. Row and column extents include declared repeated empty rows/cells and spans, but not column-style declarations alone. Repeated populated cells are bounded before loops; results are sorted by row/column. Numeric values are finite floats or lexical integers, booleans remain booleans, and dates/durations retain their original strings. Currency and percentage types remain distinguishable. Display text is retained separately, with a scalar fallback when absent. Formula text and cached results are preserved without evaluation or relative-reference rewriting; a warning states this limitation. Merges use inclusive `CellRange` coordinates. Table display styles, including parent styles, identify hidden sheets.

ODP retains every direct drawing page, even an empty page, in package order. Title/subtitle placeholders feed title; regular shape text feeds body; notes feed notes. Page thumbnails, headers, footers, metadata, and master content do not become slide body text. XML order is preserved; visual reading order, inherited master content, animation timing and rendering are not implemented. Basic drawing-page visibility styles and explicit visibility mark hidden slides.

Unsupported objects, annotations, revision containers, extensions and other unhandled content are omitted with bounded, deduplicated warnings. Unknown content is never recursively scraped for text. `meta.xml` and `settings.xml` are not opened. `styles.xml` is parsed only to resolve visibility, never for user-facing text. Embedded content and external links are not opened. No extraction files or network requests are made during parsing.

## Resource and hostile-input handling

The reader checks file size, ZIP member count (4096), aggregate declared uncompressed size (128 MiB), and every member size (64 MiB). Selected member reads are bounded. Duplicate ZIP names are rejected; encrypted ZIP flags and manifest encryption declarations raise `EncryptedDocumentError`. Bad ZIP/CRC, unsupported compression, malformed XML, and format errors use the shared exception hierarchy.

DTD/entity declarations are rejected before XML parsing, including NUL-interleaved UTF-16/32 encodings; a parser doctype callback provides a second guard. Tree construction counts nodes against `max_records`, enforces depth while starting elements, and counts source text/attribute characters before retaining them. Depth has an additional hard ceiling of 256 to protect recursive traversal. ElementTree does not fetch external resources.

Output cells (100,000), sheets (256), rows (1,048,576), columns (16,384), and text (10 million characters) are defaults; explicitly configured larger or smaller limits are honored. Slides use `max_slides`. Text accounting includes formula/cached string storage, so it is intentionally conservative. A final length calculation also checks rendered separators and spreadsheet addresses without constructing the complete rendered text. Decimal repeat/span attributes are length-checked before integer conversion. Counts, extents, and text multiplication are checked before repeated model allocation. ODT empty rows also consume cell budget because they allocate row lists. ODS empty runs remain sparse even when they span the full supported grid.

## Verification

`tests/test_odf.py` builds original ZIP/XML fixtures in memory. Namespace constants are specified independently of implementation constants. Coverage includes ordering, whitespace, sparse coordinates, values, cached formulas, merges, hidden sheets, blank slides/notes, MIME checks, duplicate members, manifest encryption, hostile declarations, and resource ceilings.

Three user-authorized local samples were read only for smoke validation. Their bytes, extracted text, and paths are not included here or in tests. No sample was copied, downloaded, or added to a public repository. The presentation sample exposed a namespace typo during development; correcting it produced four slides. Synthetic presentation tests now use independently specified namespace URIs to guard against that regression.
