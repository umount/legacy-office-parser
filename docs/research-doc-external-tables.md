# DOC: внешние свойства таблиц

## Реализовано (2026-10-21)

`src/legacy_office_parser/doc.py` обходит `sprmPTableProps` (`0x646B`)
и `sprmPHugePapx` (`0x6646`) итеративно. Общая цепочка проверяет диапазоны
Data, размер PrcData (10…0x3FA2 байт), повторные смещения активной цепочки,
`Limits.max_depth` и общий `max_records`. Data читается через обычный
ограниченный `read_stream`. Внешний массив должен содержать целые Prl;
нулевой байт выравнивания разрешён только исходному PAPX, не PrcData.

HugePapx действует только первым Prl своего массива. После обработанной
ссылки остаток содержащего её массива не применяется (и не разбирается).
Свойства до PTableProps сохраняются; PRM piece table применяется после PAPX.

`src/legacy_office_parser/_doc_table.py` реализует последовательные операции:

- TInsert: вставка в начало, середину или конец, включая создание строки с
  нуля; положительное число вставляемых ячеек, максимум 63 ячейки, ширина
  каждой 0…31680 twips, общая ширина после вставки не более 31680 twips.
- TDelete: удаление существующего полуоткрытого диапазона; минимум одна
  ячейка остаётся. Удалённая ширина вычитается из следующих границ.
- TDxaCol: назначение ширины каждой ячейке диапазона; следующие границы
  сдвигаются на разницу ширин. Нулевая ширина и пустые допустимые диапазоны
  не превращаются в ошибки. Ограничение общей ширины именно из TInsert не
  переносится без основания на TDxaCol.
- TMerge / TSplit / TVertMerge меняют флаги текущих определений сразу.
  Последующие вставки и удаления перемещают эти флаги вместе с ячейками,
  новые ячейки получают нулевые поддерживаемые флаги. Следующий TDefTable
  заменяет определения и предыдущие merge-флаги; поздние PRM меняют уже
  полученное состояние. Очереди старых merge-индексов больше нет.
- TDxaLeft / TDxaGapHalf учитываются при создании через TInsert: начало
  координат равно left − gap. Последующие изменения сдвигают границы;
  абсолютные координаты нового TDefTable не получают повторный отступ.

## Первичные источники и принятые решения

Проверены непосредственно страницы Microsoft MS-DOC, не только сторонние
конвертеры или результаты корпуса:

- [2.6.2 Paragraph Properties](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/484822ee-a9d9-4af4-8423-29fda67a6a58):
  обе ссылки, прекращение исходного массива, правило первого HugePapx,
  минимальная длина и конечность смешанных цепочек.
- [2.9.210 PrcData](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/473fd992-c824-4655-8880-3186bd432f80):
  signed cbGrpprl, верхняя граница 0x3FA2, целое число Prl.
- [2.4.3 Overview of Tables](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/5b45f0e7-7760-4fdb-af88-0146de2feb4c):
  определения через TDefTable/TInsert/TDelete, соответствие определениям
  фактических cell marks, fallback для читателей без PTableProps.
- [2.6.3 Table Properties](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/b39a6648-501c-4361-8366-4f042f579469):
  последовательные операции, происхождение новых свойств из стиля,
  TDxaLeft/GapHalf, TSplit, TIstd и preferred widths.
- [2.9.324 TInsertOperand](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/082d49fd-8f96-4fd9-ac6e-61bd7c00b90d):
  позиция, количество и пределы вставки.
- [2.9.123 ItcFirstLim](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/61341a2c-b8da-4e52-ba62-b2b0d5efadc4):
  полуоткрытый диапазон, допустимый пустой диапазон при first < cell count.
- [2.9.322 TDxaColOperand](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/fa2550bf-647e-4cfd-b468-090c6850a213):
  ширина каждой выбранной колонки, включая соответствующее spacing.
- [2.9.321 TDefTableOperand](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/de06ec41-a0ac-4046-9096-cdfaa0091ad9):
  абсолютные координаты границ, отсутствующие TC80 получают defaults.
- [2.9.343 VertMergeOperand](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-doc/cf7489ac-7eee-404d-8844-8ebbd279b77d):
  индекс текущей ячейки и формат операнда.

### Политика fallback

Сам переход по ссылке не считается доказательством поддержки геометрии.
PTableProps обрабатывается пробно с сохранением состояния и остатка исходного
массива. Если результирующее состояние не содержит определений ячеек,
пробные изменения откатываются и применяется inline-остаток с предупреждением.
Это политика извлечения, использующая возможность **не обрабатывать**
PTableProps, а не утверждение, что MS-DOC требует такого эвристического выбора.
Если определения уже были до ссылки и сохранились, они тоже считаются
поддержанной основой. Вложенный fallback пробуется раньше внешнего.

При наличии определений внешний результат принимается и исходный хвост
полностью игнорируется: не смешиваем новые TInsert с резервным TDefTable.
Повреждённая ссылка, длина, операнд, цикл или исчерпание лимита являются
ошибкой, а не поводом скрыть повреждение через fallback. Повторное использование
ранее отклонённой ссылки в другом fallback не считается циклом.

## Точные ограничения

- Это извлечение структуры, не Word layout engine. TIstd и условные табличные
  стили не вычисляются; warning сохранён. Поэтому новые ячейки получают
  defaults поддерживаемых флагов, а не полный набор свойств табличного стиля.
- F614 (TTableWidth), TCellWidth, TWidthBefore/After, TWidthIndent и включённый
  TFAutofit выдают предупреждение: preferred/automatic layout не вычисляется.
  Оно намеренно сохраняется даже при наличии explicit geometry: ссылка сама
  по себе не доказывает совпадение с отображаемыми ширинами. Режим, запрещающий
  любые warnings, вправе отклонять такие документы.
- Начало left − gap не моделирует дополнительные поправки borders/margins/
  spacing. Относительные координаты определений используются для сравнения
  строк, без вычисления полного размещения на странице.
- Удаление merge-anchor или вставка обычной ячейки внутрь merge не создаёт
  выдуманного нового anchor; orphan continuation сохраняется обычной ячейкой
  с предупреждением. Содержимое covered cells не удаляется.
- Неизвестные свойства по-прежнему не дают полной гарантии раскладки.
  Старый `0x6645`, TDefTable10 (`0xD606`) остаются неподдержанными с warning.
- Несоответствие числа cell marks и определений не порождает текст/ячейки из
  воздуха. Нулевые и неполные сетки не нормализуются; разные внешние границы
  строк сохраняют физические координаты. Вертикальное объединение требует
  совпадения явных интервалов границ.
- Проверка минимальной длины PrcData строже старой реализации HugePapx.
  Регрессии циклов и глубины используют корректные 10-байтные узлы, чтобы
  проверять именно эти условия, а не преждевременную ошибку длины.

## Проверка

`tests/test_doc_external_tables.py` самостоятельно строит WordDocument,
1Table и Data с FIB/CLX/PLC/PAPX; подменён только транспорт OLE. 64 теста
проверяют публичный parse_doc_bytes, нормализацию и координаты, merges,
вставки/удаления/ширины, origin/gap, fallback, смешанные цепочки, циклы,
размеры/усечения и бюджеты. Утверждения о внутренних границах дополнены
сквозными проверками Cell.col_span/row_span/covered/text. Тест не импортирует
fixture builders из существующих DOC-тестов.

Собственный OLE fixture и его генератор находятся в `tests/fixtures/doc_external/`
и `tools/generate_doc_external_fixture.py`; публичный API и повреждённые ссылки
проверяет `tests/test_doc_external_ole.py`. LibreOffice-сверка подтверждает
авторские данные и структуру, используя inline fallback своего читателя.

На пяти личных документах сохранены число символов/таблиц и прежний набор
расхождений с эталоном. В двух документах обрабатывается 71 ссылка PTableProps;
это количество ссылок, не потерянных таблиц. Полное равенство не заявляется.
Личные документы и содержимое не публикуются.

Все ссылки здесь адресуют поток Data внутри текущего DOC; сетевых обращений
или чтения ресурсов, указанных в документе, нет.
